# Paper服务器搭建：不用敲命令也能开起来，面板和VPS两条路线、配置档位和真实价格一次说清

搜「Paper服务器搭建」的人，其实分成两拨，需求差得很远。

一拨只是想先跑起来看看：下载 paper.jar，装个 Java，本地开起来和朋友玩一会儿，关掉就完事。另一拨是要 7×24 在线的服，玩家随时能连，地图和插件不能丢。这两拨人需要看的内容完全不一样，而大部分教程把它们混在一起讲，结果两拨都看不懂。

下面把两条路线拆开写。你只需要读自己那一半。

## 先确认 Paper 对环境的硬性要求

Paper 是 Spigot 和 CraftBukkit 的直接替代品，插件不用改，从原版存档迁过来它会自己转数据。省事是省事，但 Java 版本对不上，服务器直接起不来。

官方文档给的对应关系是这样的：

| Paper 版本 | 建议 Java 版本 |
| --- | --- |
| 1.7.10 – 1.11 | Java 8 |
| 1.12 – 1.16.4 | Java 11 |
| 1.16.5 | Java 16 |
| 1.17 – 1.19 | Java 17 |
| 1.20 – 1.21.11 | Java 21 |
| 26.1 及以上 | Java 25 |

装错版本的典型症状是控制台报一堆看不懂的 class 错误，然后进程退出。先 `java -version` 看一眼，比事后查半天报错快得多。

另外两条容易被忽略：第一次启动会生成 `eula.txt`，把里面的 `false` 改成 `true` 才能继续；默认端口是 25565，防火墙和端口映射都要对着这个数字配。

## 路线 A：用面板开 Paper，全程点鼠标

如果你不打算学 Linux，也不想知道 systemd 是什么，这条路更合适。

雨云的游戏云分两种形态，其中**面板游戏云**是基于容器化（Docker / K8S）的，通过网页面板管理，定位就是「快速搭建常见游戏服务器」。它的服务端列表里直接就有 Paper，同一个列表里还有纯净版、Forge、Fabric、Purpur、Mohist、CatServer、NeoForge。

流程大致是：

1. 在控制台买一台面板游戏云，按需选 CPU 机型、核心数、内存和硬盘
2. 进「我的游戏云」，点管理进入面板
3. 在「重装 / 切换游戏」里选 Minecraft，服务端选 Paper
4. 点开启，等到控制台出现 `Done` 就是开好了
5. 面板里改 `server.properties`（关正版验证、调最大人数、调视距都在这里），改完重启
6. 把面板给的地址加进游戏的「多人游戏 → 添加服务器」

雨云自研的面板还带 CPU 升降级、备份和 MySQL，对单端小服来说够用。如果是纯新手，MCSM 面板也在同一产品线里，可以免费领取，走的是可视化 + SFTP 那套。

> 一个实际提示：面板机型的公开参数是 10G 免费存储、50M 上行配 200M 下行。低版本纯原版服够用，但如果你要挂 100 个以上的模组，光靠这两项看着够，实际会被内存和单核性能卡住，不是带宽的问题。

## 路线 B：买游戏云 VPS 自己部署

有完整系统权限、想多开、想自己装环境、想加独立公网 IP 的，选 VPS 游戏云。跑 Paper 的完整步骤：

**1. 装 Java**

按上面的表选版本。比如 1.20 以上的服：

bash
sudo apt update && sudo apt install -y openjdk-21-jre-headless
java -version


**2. 下载 paper.jar**

Paper 现在通过 `fill.papermc.io` 的 Fill API 分发构建，每个响应都带 SHA-256 校验值。老的 `api.papermc.io/v2` 已经返回 410 Gone，还在用过时脚本拉服务的，这里会直接断掉。

**3. 建目录、放 jar、启一次**

bash
mkdir -p /opt/minecraft/paper && cd /opt/minecraft/paper
java -Xms4G -Xmx4G -jar paper.jar --nogui


`-Xms` 和 `-Xmx` 是初始和最大堆内存，两个值写成一样可以避免运行中反复扩展堆带来的卡顿。`--nogui` 是关掉原版那个图形窗口，命令行环境不需要它。

**4. 接受 EULA**

第一次启动会因为没接受协议而退出。打开生成的 `eula.txt`，把 `eula=false` 改成 `eula=true`，再启动。

**5. 做成开机自启**

真正长期在跑的服不该靠一个终端窗口吊着。写个 systemd 服务，`systemctl enable` 之后机器重启服务会自己起来，比 `screen` 里挂着稳。

**6. 开端口**

默认 25565。雨云游戏云 VPS 允许自助开放端口，面板里配映射就行；用 NAT 机型的话记得连的是映射后的地址和端口，不是服务器内网 IP。

## 两条路线怎么选

|  | 面板游戏云 | VPS 游戏云 |
| --- | --- | --- |
| 权限 | 容器内，面板托管 | 完整系统权限 |
| 上手难度 | 点几下就好 | 需要会基本 Linux 命令 |
| 独立 IP | 不方便 | 可加购 |
| 服务端多开 | 单端为主 | 支持 |
| 适合谁 | 新手服主、朋友服 | 多服、代理、想折腾环境的人 |

判断标准其实很简单：你会不会去改 `paper-global.yml` 里那些参数。会，就买 VPS；不会，面板更省心。

## 配置选多大，看人数和模组量

官方给的参考基准是：纯净/基岩服按视距 6 估，MOD 服按 50 个 mod、视距 5 估，Fabric 服按 15 个 mod、视距 5 估。同时 1.18 之后的版本消耗大约是 1.16 的两倍、1.12.2 的三倍。

换句话说，同一个 2核4G 的机器，开 1.12.2 纯净服能带一批人，开 1.20 的大型整合包可能一个人都卡。这也是为什么很多教程里「4核8G 够用」的结论放到高版本模组服上完全不成立。

社区里较常见的一个配置结论是：1.17 以上的服，优先挑高主频 CPU，4核8G 起步。MC 服务端多核优化差，加核心的收益远小于提主频。

## 计费模式：这才是真正省钱的地方

雨云游戏云有固定计费和动态计费两种，选错了比选错配置更浪费钱。

固定计费就是传统月租，跑满一个月多少钱就是多少钱。动态计费是低价基础月租加"CPU 电费"——CPU 使用率基准值 20%，低于 20% 的部分不算耗电，超出的部分按日结算。内存等其他硬件不产生电费。

所以：

- 每天开服 2 小时以上，选固定计费，稳定运行不会有额外扣费
- 每周只玩两个晚上、平时服务器空转的，动态计费明显更划算
- 只是想测试某个整合包能不能跑，先买动态计费试一天

这个设计对"朋友服"特别友好。工作日没人上线的时候，CPU 基本闲着，不烧电量。

## 几个真正会踩的坑

**Java 版本没对。** 前面那张表是最常出问题的地方，尤其是 1.16.5 要 Java 16 这种反直觉的档位。

**内存给太少。** 2G 挂几个插件就开始 GC 卡顿，4G 能撑小服。不要按"我只有 5 个人玩"来估内存，要按你装的插件和模组数量估。

**视距拉满。** 视距是性能杀手，玩家端的视距和服务器端的 `view-distance` 是两回事。服务器端调到 6–8 通常就够了，模组服干脆调到 5。

**没做备份。** 装备、建筑、领地数据丢一次就够难受的。面板机型自带备份功能，VPS 机型要自己写定时脚本，别等出事才想起来。

**把网站和游戏服塞一台机器。** 如果你还想在同一台机器上跑 80/443 的网站，那就涉及域名备案和过白流程了。游戏服用的 25565 这类端口不走这套要求，但两者混在一起会让事情变复杂。

## 常见问题

**Paper 和原版、Spigot 差在哪？**
Paper 是 Spigot 的分支，性能优化更多、修复的漏洞更多，同时对 Spigot 和 CraftBukkit 插件完全兼容。原版服务端不支持插件，如果你要用 EssentialsX、LuckPerms、WorldGuard 这类插件，必须换 Paper 或同类服务端。

**开服需要备案吗？**
游戏端口不涉及 HTTP 备案要求。国内机器上跑网站走 80/443 才需要先备案再过白。
